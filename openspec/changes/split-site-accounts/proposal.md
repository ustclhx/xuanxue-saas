# Proposal

## Why

Owner 已拍板：干支日（ganjiday.com）与 Arcanumber（arcanumber.com）由 Lucinum LLC 运营，两站的账户、积分、购买、付款与退款记录**彼此独立**。#93 法律页文案已经按这个口径改好，但现有实现是两站共用一套账户：

- `user.email` 全局唯一，同一邮箱在两站登录得到的是同一个用户；
- 积分、订单、退款与报告挂在这个用户的个人空间下，在两个站点里看到的余额和记录完全相同。

所以法律文案目前与实际行为不符，#93 不能合并。本 change 让实现符合拍板的口径。隔离层级已定为**分站身份**（同一邮箱在两站是两个完全独立的用户），不采用「共用登录、分站空间」。

## What Changes

- **BREAKING** 用户归属站点：
  - `user` 增加 `site` 列（`east` / `west`），唯一约束由 `email` 改为 `(site, email)`；
  - 同一邮箱可以在两站分别注册，得到两个独立用户，密码、两步验证与 Google 登录各自绑定。
- 认证数据层按站点隔离：
  - 每个请求创建的 Better Auth 实例带上当前站点；
  - 包装 drizzle adapter，对 `user`、`account`、`verification` 的读写自动附加 `site` 条件，新建记录写入 `site`；
  - `account`、`verification` 同样增加 `site` 列。
  - 效果：一个站点的会话、验证码、重置链接与 OAuth 关联，在另一个站点都无效。
- 站点判定：
  - 账户站点取自请求 Host（`resolveSite`）；
  - staging 等预览 Host 统一视为西方站；
  - 不接受客户端指定站点。
- 空间归属站点：`organization` 增加 `site` 列，个人空间的站点与所属用户一致。积分、购买、付款、退款申请、报告与 Billing 列表原本就按空间划分，因此随之按站点隔离；团队空间只能邀请同站用户。
- 应用代码中**按邮箱查找用户**的入口全部按当前站点限定，包括：
  - 后台用户搜索、团队邀请、管理员引导名单；
  - 删号流程与其他直接 SQL 查询。
- 删号只影响本站账户；本站删号后，同一邮箱仍可在本站重新注册。另一站的同邮箱账户不受影响。
- 后台：
  - 用户、空间与计费列表显示站点并可按站点筛选，默认显示当前站点；
  - 模拟登录只能针对当前站点的用户；
  - 管理员身份也按站点：名单内的邮箱需要在每个站点各自注册并验证后才提升为管理员。
- 存量迁移：
  - 每个现有用户拆成两站各一个账户（Owner 已定；现有用户都是测试用户）。原用户与其空间、积分、报告留在「主站点」，判定依据依次为：已有详批的类型（八字、紫微、四柱、宫合 → 东方；灵数 → 西方），其次用户语言（zh-Hant / zh-Hans / ko → 东方，其余 → 西方），都没有时为西方；
  - 另一站新建副本账户：复制邮箱、姓名与登录方式，空间为空，不复制积分与记录；
  - 验证码与未过期的重置链接直接作废。
- #93 法律页：本 change 上线后，再核对文案与行为一致并合并。

## Capabilities

### New Capabilities

（无。账户站点归属并入 `multi-site` 与 `user-auth`。）

### Modified Capabilities

- `multi-site`：「账号与付费跨站可用」改为两站各自提供登录与付费，账户、积分与记录按站点独立，会话不能跨站使用。
- `user-auth`：新增「账户归属站点」：注册、登录、找回密码、验证码与 OAuth 都只在当前站点内生效。
- `workspace-tenancy`：个人空间属于用户所在站点；团队空间成员限同站用户。
- `account-deletion`：删号与「同一邮箱可重新注册」只作用于本站。
- `admin-console`：用户、空间与计费按站点查看与筛选；模拟登录限当前站点用户。
- `admin-bootstrap`：管理员引导名单在每个站点分别生效。

## Impact

- **数据库**：新增迁移，为 `user`、`account`、`verification`、`organization` 增加 `site` 列并回填；`user` 的唯一约束改为 `(site, email)`；相关索引同步调整。必须先在 staging 预演，再上生产。
- **packages/auth**：
  - `createAuth` 接收站点并包装 adapter；
  - 个人空间写入站点；
  - 管理员引导、团队邀请与删号按站点限定。
- **apps/web**：
  - 由 server 入口解析站点后传给 auth；
  - 后台用户、空间与审计列表增加站点列与筛选；
  - 设置页与改邮箱流程按站点校验唯一。
- **apps/jobs**：
  - 指标 Cron 按站点统计用户数；
  - 发信沿用用户所在站点的品牌与发件人。
- **packages/billing**：
  - 付款与订单仍按空间关联，无结构性改动；
  - 回调中查找用户时带上站点。
- **风险**：
  - 这次改动深入 Better Auth 的数据访问层，升级 Better Auth 时必须重跑本 change 的隔离测试；
  - 漏掉一处按邮箱查询，就可能把另一站的用户查出来，所以要加一项检查脚本，扫描未限定站点的 `user.email` 查询。
- **依赖与顺序**：
  - 合并 #93 依赖本 change 上线；
  - 本 change 不涉及生产 PayPal 配置；
  - 生产迁移需要 Owner 批准，并在发版窗口内执行。
